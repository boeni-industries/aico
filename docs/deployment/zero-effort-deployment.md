# Zero-Effort AICO Deployment

## Quick Start: Deploy Everything with Zero Manual Steps

This is the canonical way to go from **zero → fully operational** on a single Docker host.

Prerequisites (from a fresh repo clone):
- Install **Docker** and ensure the Docker daemon is running.
- Install **uv** and ensure you have **Python >= 3.13** available.
- Initialize config templates once (idempotent):
  ```bash
  uv run --project cli aico config init
  ```

Then run the one-command bootstrap:

```bash
uv run --project cli aico deploy system \
  --non-interactive \
  --tenant-display-name "My Deployment" \
  --admin-full-name "Owner Admin" \
  --admin-pin "ChangeMe-Strong1!"
```

This provisions:
- Postgres (container + schema)
- Tenant + admin/owner bootstrap
- Gateway + Core + Modelservice containers (disable with `--no-services`)

Headless master password provisioning:
- Set `AICO_MASTER_PASSWORD` (supported) or pass `--master-password-file`.
- The deploy command removes `AICO_MASTER_PASSWORD` from its own process environment after consuming it, and will not forward it into any `docker compose` subprocess environment.

Bootstrap semantics:
- The earliest-created active non-system user (`user_profiles.uuid != 'system_user'`) is ensured to be:
  - `owner` in `tenant_memberships` for the bootstrapped tenant
  - `admin` in `auth_access_policies` (`resource_type='role'`, `permission='admin'`)
- Deploy state is persisted under `AICO_DATA_DIR/runtime/deploy-state.yaml` for safe re-runs.

## Advanced: Deploy components individually

You can still deploy components individually. **No credential setup required.**

```bash
# Deploy infrastructure
uv run aico deploy pg --nuke
uv run aico deploy influx --nuke
uv run aico deploy loki --nuke
uv run aico deploy grafana --nuke

# Deploy AICO services
uv run aico deploy gateway --nuke
uv run aico deploy core --nuke
uv run aico deploy modelservice --nuke

# Deploy Studio UI
uv run aico deploy studio --nuke --dev
```

**That's it.** All credentials are automatically generated, saved, and reused.

## How It Works

### Automatic Credential Management

Each deploy command:
1. **Checks `docker/.env`** - Reuses existing credentials if found
2. **Checks environment variables** - Uses if set, saves to `.env`
3. **Auto-generates** - Creates secure credentials and saves to `.env`

### First Run (No Credentials)

```bash
$ uv run aico deploy pg --nuke

============================================================
🗄️  AICO Postgres Deployment
============================================================

ℹ️  Auto-generating Postgres password...
✅ Postgres password generated and saved to docker/.env
🚀 Starting Postgres container...
✅ Postgres deployment completed successfully!
```

Credentials are saved to `docker/.env`:
```bash
AICO_PG_PASSWORD=xK9mP2vL8qR4wN6tY3hJ5bF7cD1aE0sG
```

### Subsequent Runs (Credentials Exist)

```bash
$ uv run aico deploy pg --nuke

============================================================
🗄️  AICO Postgres Deployment
============================================================

ℹ️  Using Postgres password from docker/.env
🚀 Starting Postgres container...
✅ Postgres deployment completed successfully!
```

Same credentials are reused automatically.

## Credential Persistence

All credentials are stored in `docker/.env`:

```bash
# Auto-generated by AICO deploy commands
AICO_PG_PASSWORD=xK9mP2vL8qR4wN6tY3hJ5bF7cD1aE0sG
AICO_INFLUX_ADMIN_PASSWORD=aB3cD5eF7gH9iJ1kL2mN4oP6qR8sT0uV
AICO_INFLUX_ADMIN_TOKEN=wX1yZ2aB3cD4eF5gH6iJ7kL8mN9oP0qR1sT2uV3wX4yZ5
```

**File permissions**: Automatically set to `600` (owner read/write only)

**Location**: `<aico-repo>/docker/.env`

## Override Credentials (Optional)

If you want to use specific credentials:

```bash
# Set environment variable before deploy
export AICO_PG_PASSWORD="my-custom-password"
uv run aico deploy pg --nuke
```

The custom password will be saved to `docker/.env` for future use.

```bash

```

## Credential Security

### Local Development
- Credentials stored in `docker/.env` with `600` permissions
- File is gitignored (never committed)
- Secure random generation (32-48 bytes)

### Production Deployment
Use environment variables or Docker secrets:

```bash
# Option 1: Environment variables
export AICO_PG_PASSWORD="production-password"
uv run aico deploy pg

# Option 2: Docker secrets (recommended)
echo "production-password" | docker secret create postgres_password -
```

## Troubleshooting

### "Permission denied" on docker/.env

The file is automatically created with restricted permissions. If you need to view it:

```bash
cat docker/.env
```

### Reset All Credentials

Delete the `.env` file and redeploy:

```bash
rm docker/.env
uv run aico deploy pg --nuke
```

New credentials will be auto-generated.

### View Current Credentials

```bash
cat docker/.env
```

Or check specific credential:

```bash
grep AICO_PG_PASSWORD docker/.env
```

## CI/CD Integration

For CI/CD pipelines, set credentials as secrets:

```yaml
# GitHub Actions example
env:
  AICO_PG_PASSWORD: ${{ secrets.AICO_PG_PASSWORD }}
  AICO_INFLUX_ADMIN_TOKEN: ${{ secrets.AICO_INFLUX_ADMIN_TOKEN }}

steps:
  - name: Deploy AICO
    run: |
      uv run aico deploy pg --nuke
      uv run aico deploy influx --nuke
```

Credentials from environment variables are automatically saved to `docker/.env` for the deployment.
